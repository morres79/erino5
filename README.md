# ТСЖ «Еринские Высоты»

PHP-сайт с новостями в MySQL/MariaDB, управлением публикациями и закрытыми обсуждениями собственников. Общие шаблоны и оформление прежнего сайта сохранены. Node.js и сборка фронтенда не нужны.

## Страницы и публикация

- `index.php`: текущие опубликованные новости из БД, по 10 записей на страницу. Раздел «Важные объявления» также формируется из таблицы news: только опубликованные записи с отметкой is_important. Они не дублируются в общей ленте и не зависят от её пагинации.
- `archive.php`: архивные новости из БД, по 10 записей на страницу, от новых к старым.
- `news.php?id=N`: отдельная опубликованная или архивная новость. Старый адрес `news.php` без ID перенаправляет на главную. Отдельный пункт «Новости» в горизонтальном меню убран.
- `admin.php`: создание и редактирование новостей, проверка собственников, модерация комментариев. Раздел новостей — таблица ID / Тема / Статус с выбором 20, 50 или 100 строк и пагинацией. Тема открывает редактор либо просмотр архивной/удалённой записи; только статус «Опубликована» является ссылкой на публичную новость. При открытии и сохранении записи сохраняются размер страницы и позиция таблицы.
- `account.php`: вход, заявка собственника, выход и смена пароля.

Статусы новости:

- **Черновик** — сохранён в БД и виден только администратору.
- **Опубликована** — отображается на главной и доступна по своей ссылке. Отметка **«Важное объявление»** переносит запись в одноимённый раздел вместо общей ленты; снятие отметки возвращает её обратно.
- **В архиве** — отображается в архиве и по прежней ссылке, добавление комментариев закрыто. Подтверждённые собственники могут читать сохранённую историю обсуждения, если оно было включено. Гостям история не раскрывается.

**Удалена** — скрыта на всех публичных страницах, включая прямую ссылку, и видна только в управлении. Для удаления выберите «Удалить» в статусе и сохраните либо нажмите отдельную кнопку «Удалить новость». Кнопка доступна и для архива, не изменяет текст и не требует открывать редактирование. В таблице удалённая запись показана бледным перечёркнутым текстом. Текст, ID, настройки и комментарии остаются в БД. Для восстановления нажмите «Перевести в черновик»; после проверки можно опубликовать запись. Прямая публикация и редактирование удалённой записи запрещены на сервере.

Чтобы перенести запись в архив, откройте её в управлении, выберите «В архиве» и нажмите «Сохранить». Архивная запись в управлении открывается только для чтения. Для возврата сначала нажмите «Перевести в черновик», затем отредактируйте запись и сохраните со статусом «Опубликована». Прямое изменение текста, подписи, обсуждения или публикация из архива запрещены на сервере, в том числе из ранее открытой формы. После сохранения редактор остаётся открытым с текстом, сообщением о результате и временем последнего сохранения. Поля сохраняются в форме при ошибке проверки.

## Оформление новости

Наведите указатель на компактную кнопку с иконкой, чтобы увидеть её назначение. Выделите фрагмент текста и используйте кнопки «Жирный», «Курсив», «Важное сообщение», «Примечание», «Маркированный список» и «Нумерованный список». Для списка выделите несколько строк: каждая непустая строка станет пунктом. Внутри текста работают Ctrl+B и Ctrl+I (Cmd+B/Cmd+I на macOS).

Хранимые обозначения:

- `[b]текст[/b]`, `[i]текст[/i]` — выделение;
- `[alert]текст[/alert]`, `[comment]текст[/comment]` — блоки `inf_alert` и `inf_comment`;
- `[ul][li]пункт[/li][/ul]`, `[ol][li]пункт[/li][/ol]` — списки;
- `[url=Doc/2026/file.PDF]Документ[/url]` — ссылка;
- `[sup]2[/sup]`, `[h5]заголовок[/h5]`, `[h6]заголовок[/h6]`, `[important]текст[/important]` — сохранённое оформление старых записей;
- `[table][tr][td]ячейка[/td][td]ячейка[/td][/tr][/table]` — таблицы из архива; также поддерживается `[th]`.

Вложенные списки и вложение одного блока alert/comment в другой не поддерживаются. Выделение и списки работают внутри важных сообщений и примечаний. Произвольный HTML экранируется, опасные схемы ссылок не используются.

Поле подписи хранится отдельно и выводится последним блоком `inf_sign`. Для новой записи предложено «Администрация ТСЖ»; поле можно изменить или очистить. Предпросмотр сохранённой записи, главная, архив и отдельная страница используют один форматтер. Цвет ссылок-заголовков совпадает с цветом прежнего `inf_header`. Под новостью используется небольшая приглушённая ссылка «Перейти ->».

## Перенос старых новостей

В `erino5` перенесены 27 записей: 4 прежние новости главной получили статус `published`, 23 новости старого архива — `archived`. Дополнительно четыре прежних важных объявления перенесены в ту же таблицу со статусом published и признаком is_important=1. Статический текст объявлений удалён из index.php; их можно редактировать через управление. Все текстовые фрагменты, 114 ссылок и две таблицы сверены с исходниками. Телевизионный опрос сохранён как исторический текст с вариантами ответов, без активной формы голосования.

`database/legacy/index.html` и `archive.html` — снимки страниц до удаления статических новостей. `database/legacy/news.json` — подготовленный файл переноса. Его можно воспроизвести командой `php tools/prepare_legacy.php`; скрипт читает именно снимки и не выполняет их PHP-код. Регистр путей к документам приведён к фактическим именам в `Doc/`; файлов, отсутствующих в репозитории, не обнаружено.

Точные даты публикации известны не для каждой старой записи. Импорт не придумывает даты: `published_at` у перенесённых записей оставлен NULL, исходный порядок сохранён в `legacy_order`. При первоначальном импорте идентификаторы существовавших новостей сохранялись. Затем выполнена отдельная перенумерация всей ленты по хронологии: старейшая запись имеет ID 1, новейшая — максимальный ID. На главной, в архиве и управлении используется сортировка по ID по убыванию. Для старых записей хронология восстановлена по legacy_order; для созданных через форму — по created_at и прежнему ID.

У каждой импортированной записи есть уникальный `legacy_key`, поэтому повторный запуск не создаёт дублей и не перезаписывает последующие изменения редактора. Редактируйте перенесённые новости через `admin.php`, а не повторной загрузкой JSON.

Для другой установки:

1. Выполните `php tools/manage.php migrate` с подключением, имеющим право ALTER, или импортируйте SQL из `database/migrations/` в нужную БД.
2. `php tools/import_legacy.php` — проверка без записи.
3. `php tools/import_legacy.php --apply` — импорт в транзакции с приватной резервной копией существующих новостей и комментариев. По умолчанию копия создаётся вне публичного сайта: `../.private/backups/`. Для другого пути используйте `--backup-dir=/private/path`.

Для переноса важных объявлений выполните `php tools/import_legacy.php --important` (проверка) и `php tools/import_legacy.php --important --apply` (запись с резервной копией). Файл `database/legacy/important.json` воспроизводится командой `php tools/prepare_important.php`. Исходный порядок четырёх объявлений на главной сохранён, даты публикации не придуманы. Миграция `003_important_news.sql` добавляет is_important с нулевым значением для существующих новостей. Статус deleted хранится в существующем поле status; физическое удаление новостей не выполняется.

Импорт не удаляет и не перенумеровывает существующие записи. При ошибке транзакция откатывается. На базе разработки обновление схемы и импорт уже выполнены.

## База и окружение

PHP 8.1+ с `pdo_mysql`, `session`, `iconv`; для TLS необходимо `openssl`. MySQL 8+ или MariaDB 10.6+, InnoDB, utf8mb4. На сервере 195.189.181.72 используется MySQL 8.0.46, база `erino5`.

Локальный приватный конфиг: `D:/web/erino5.ru/.private/database.php`. Приложение использует отдельного пользователя `erino5_dev_app` с правами SELECT/INSERT/UPDATE/DELETE только на эту базу и обязательным TLS. Административные реквизиты БД приложение не хранит.

При переносе скопируйте `config.example.php` за пределы публичной папки и задайте `ERINO_CONFIG` с его абсолютным путём. Альтернатива — `ERINO_DB_DSN`, `ERINO_DB_USER`, `ERINO_DB_PASSWORD`. Локально при отсутствии этих настроек загружается `../.private/database.php` относительно папки сайта.

Для новой базы выполните `php tools/manage.php install`, для обновления — `php tools/manage.php migrate`. Создание схемы требует прав CREATE/INDEX, первое применение миграций — ALTER. Обычному пользователю приложения эти права не нужны. Установка не должна запускаться против чужой базы с совпадающими именами таблиц.

Настройка `ssl: true` требует шифрованное подключение. Проверка сертификата включена по умолчанию; `ssl_ca` задаёт доверенный CA-файл. В приватном конфиге разработки пока используется `ssl_verify: false` (шифрование без проверки CA). Перед размещением на боевом хостинге задайте доверенный CA и включите проверку. PHP CLI и веб-сервер должны получать один и тот же конфиг.

Возможности PHP/MySQL у 1gb.ru описаны в [документации хостинга](https://www.1gb.ru/services_compatability.php); доступность версии и БД зависит от подключённых услуг аккаунта. Действующий сайт erino5.ru в ходе этих изменений не обновлялся.

## Docker для локальной работы

`docker compose up -d --build web` запускает сайт на `http://localhost:8080` с IPv4 и IPv6 loopback. Приватный файл `../.private/database.php` подключается только для чтения к `/run/secrets/erino5_database.php`, а `ERINO_CONFIG` указывает на этот путь. Перед запуском файл должен существовать.

Изменения исходников видны через bind mount. После изменения compose-файла выполните `docker compose up -d --no-deps --no-build web`. Локальная настройка `.docker/local-apache.conf` отключает постоянные HTTP-соединения, из-за которых наблюдалась задержка загрузки в браузере. Настройки Xdebug находятся в `.docker/xdebug.ini`.

## Доступ собственников

Новый аккаунт получает статус `pending`. Представитель ТСЖ проверяет право собственности вне сайта, затем подтверждает доступ. Указание номера квартиры само по себе не является подтверждением. Блокировка закрывает доступ при следующем запросе даже в существующей сессии. В комментариях показывается имя; email и квартира скрыты.

Администратор сайта: `tszadmin@erino5.ru`. Начальный пароль находится в `../.private/initial-admin.txt`, если файл ещё сохранён и пароль не менялся. После первого входа пароль нужно изменить в личном кабинете.

CLI: `php tools/manage.php admin EMAIL` создаёт нового администратора со случайным паролем; `php tools/manage.php reset-password EMAIL` выдаёт новый случайный пароль существующему аккаунту. Команды не отправляют почту и не подтверждают право собственности. Существующие аккаунты не повышаются до администратора неявно.

Пароли хешируются PHP. Изменяющие запросы требуют CSRF-токен. SQL использует параметры. Ограничения попыток входа, регистрации и комментариев хранятся в БД. Служебные каталоги закрыты `.htaccess`; на другом веб-сервере закройте `app/`, `tools/`, `tests/`, `database/` его конфигурацией. Приватные файлы и копии не размещайте в публичном каталоге.

## Проверки

- `php tests/news_format.php` — форматирование, списки, ссылки, таблицы и экранирование.
- `php tests/legacy_news.php` — сравнение всех 27 записей с исходными страницами, включая ссылки и таблицы.
- `python tests/integration.py --php /path/to/php --extension-dir /path/to/php/ext` — изолированные HTTP-проверки на временной SQLite-БД: новости, собственники, обсуждения, архив, импорт, копия и защита от дублей. Реальная БД не используется. Для PHP с уже включённым pdo_sqlite флаг extension-dir не нужен.
- `python tests/mysql_smoke.py --php /path/to/php --extension-dir /path/to/php/ext --mysql-bin /path/to/mysql/bin` — схема, миграции, транзакции и запросы на отдельном временном MySQL. Существующие экземпляры не используются.
- `python tests/remote_check.py --php D:/web/php8/php.exe --extension-dir D:/web/php8/ext --private-dir D:/web/erino5.ru/.private` — проверка реального подключения и входа через временный локальный сервер. Использует начальный пароль, поэтому после его смены проверка входа требует актуальных реквизитов. Меняются только счётчики входа.
## Хронологическая нумерация ID

В базе разработки 28 записей перенумерованы в диапазон 1–28; следующая новая запись получит ID 29. Тексты, подписи, статусы, даты и остальные поля сохранены. Внешние ключи комментариев перенесены вместе с записями. Резервная копия исходных строк и таблица соответствия прежних и новых ID находятся в `../.private/backups/news-before-reindex-*.json`.

Новостные ID в адресах `news.php?id=N` и `admin.php?edit=N` изменились. После перенумерации обновите страницу управления и используйте ссылки с новой нумерацией. Открытые до операции формы блокируются старым CSRF-токеном; сам вход пользователя сохраняется.

Просмотр плана без записи: `php tools/reindex_news.php`. Для локальной установки с Docker используйте `python tools/run_news_reindex.py --php D:/web/php8/php.exe --extension-dir D:/web/php8/ext --user guru --apply`. Управляющий пароль вводится скрыто, не сохраняется в исходниках и не передаётся в аргументах процессов. Скрипт останавливает только сервис web этого проекта и запускает его в конце операции. При фактическом изменении ID обновляется локальный маркер `app/.news-id-revision`, исключённый из Git.

Утилита сохраняет приватную копию новостей и комментариев, переносит записи через временный диапазон ID в транзакции с включёнными внешними ключами и проверяет все поля перед фиксацией. После фиксации для MySQL отдельно сбрасывает AUTO_INCREMENT на следующий номер; это требует права ALTER. При ошибке сброса счётчика утилита сообщает, что ID уже сохранены: повторный запуск завершает настройку без повторного перемещения корректно пронумерованных строк. Операция не предназначена для выполнения во время записи в эту же БД с другого веб-сервера.

Перенумерация, привязка комментариев, резервная копия, повторный запуск, следующий номер и защита старых форм проверяются интеграционными тестами. MySQL smoke-тест дополнительно проверяет реальные внешние ключи и AUTO_INCREMENT на временном сервере.
