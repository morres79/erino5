# ТСЖ «Еринские Высоты»

Существующие PHP-страницы сохранены. Новые новости, аккаунты и обсуждения работают через PDO и MySQL/MariaDB. Фреймворк, Node.js и сборка не нужны.

## Требования

PHP 8.1+ с расширениями `pdo_mysql`, `session`, `iconv`; для TLS также `openssl`; MySQL 8+ или MariaDB 10.6+, InnoDB, utf8mb4. Включите HTTPS. Версия сервера `8.0.46-0ubuntu0.24.04.4` соответствует MySQL, а не MariaDB. SQL не использует специфичные для MySQL 8 функции.

## Подключение

1. Создайте отдельную базу и пользователя приложения. Адрес сервера сам по себе недостаточен: нужны имя базы, логин и пароль. Не используйте root. Разрешите подключение от IP веб-сервера, настройте проверяемый TLS для внешней БД.
2. Скопируйте `config.example.php` **за пределы публичной папки** сайта, заполните реквизиты. Задайте переменную окружения `ERINO_CONFIG` с абсолютным путём к этому файлу. Для Apache можно задать `SetEnv ERINO_CONFIG /private/path/erino-config.php` в конфигурации виртуального хоста или поддерживаемом хостингом `.htaccess`. Не размещайте заполненный файл в репозитории или публичной папке.
3. Альтернатива: переменные `ERINO_DB_DSN`, `ERINO_DB_USER`, `ERINO_DB_PASSWORD`. DSN: `mysql:host=195.189.181.72;port=3306;dbname=ИМЯ_БАЗЫ;charset=utf8mb4`. Для боевого хостинга измените адрес согласно настройкам 1gb.ru. Параметр `ssl_ca` в приватном конфиге включает проверку сертификата БД; он требует расширения pdo_mysql.
4. Запустите `php tools/manage.php install` с тем же окружением. Установка создаёт таблицы и не удаляет существующие данные. Если SSH/CLI недоступен, импортируйте `database/schema.sql` через phpMyAdmin; первого администратора создайте локальным CLI с подключением к этой БД.
5. Запустите `php tools/manage.php admin admin@example.ru`. Команда создаёт нового администратора и один раз выводит случайный пароль. Сохраните его безопасно, войдите через `account.php` и измените пароль. Команда отказывается повышать права существующего аккаунта.
6. После установки пользователю приложения нужны только SELECT, INSERT, UPDATE, DELETE на его таблицы; CREATE и INDEX можно отозвать. Не выполняйте установку против чужой или общей базы с совпадающими именами таблиц.

PHP в CLI и на веб-сервере должен получать один конфиг. После переноса проверьте права чтения приватного файла. Не задавайте секреты в параметрах командной строки.

## Работа

- `admin.php`: добавление, редактирование, черновики/публикация, включение обсуждений, проверка заявок и блокировка собственников, удаление комментариев. Снять новость с публикации можно, переведя в черновик. Страницы управления имеют пагинацию.
- `account.php`: регистрация, вход, выход, смена пароля. Новый аккаунт имеет статус `pending`. ТСЖ проверяет собственника вне сайта, затем меняет статус на `approved`. Одного указания номера квартиры недостаточно. Самостоятельного назначения ролей нет.
- `news.php`: лента и отдельные новости. Читать и писать комментарии могут только подтверждённые аккаунты, когда обсуждение включено. При блокировке проверка следующего запроса закрывает доступ даже в уже открытой сессии. Email и квартиры в комментариях не показываются.
- Главная показывает 10 новых публикаций перед существующими объявлениями. Старые новости и архив оставлены без изменения; они пока редактируются прежним способом. Новые публикации полностью управляются формой.
- Текст новостей и комментариев — обычный текст с переносами; HTML экранируется. Загрузки файлов, редактор HTML, отправка почты и интеграция старого форума не добавлены.
- Восстановление доступа: уполномоченный администратор запускает `php tools/manage.php reset-password EMAIL`, затем передаёт новый случайный пароль проверенному владельцу безопасным способом. Сброс не подтверждает и не разблокирует аккаунт.

Пароли хешируются стандартной функцией PHP. Все изменяющие веб-запросы требуют CSRF-токен. SQL-параметры передаются отдельно от текста запроса. Ограничения попыток входа, регистрации и комментариев хранятся в БД. Нет демонстрационного администратора или пароля по умолчанию.

## Проверка

Проверка синтаксиса: `php -l ИМЯ_ФАЙЛА.php`.

Интеграционные тесты: `python tests/integration.py --php /path/to/php --extension-dir /path/to/php/ext`. Требуются Python 3 и PHP с `pdo_sqlite`; на Unix с уже включённым драйвером флаг `--extension-dir` не нужен. Тесты запускают временный PHP-сервер на loopback, создают временную SQLite-БД и удаляют её при завершении. Реальная база и её реквизиты не используются. Проверяются доступ к черновикам и обсуждениям, CSRF, XSS, подтверждение/блокировка, публикация/редактирование, модерация, лимиты, регистрация и смена пароля. MySQL SQL-схему и работу реального подключения нужно дополнительно проверить на целевой БД.

Перед выпуском настройте резервное копирование БД, HTTPS, выбранную версию PHP и `display_errors=Off`; выполните тест публикации и подтверждения собственника на хостинге. До настройки БД главная продолжает показывать существующие объявления, новые разделы выводят сообщение о недоступности.

Служебные каталоги закрыты `.htaccess`; CLI-команда дополнительно проверяет PHP_SAPI. Если используется другой веб-сервер, запретите HTTP-доступ к `app/`, `tools/`, `database/`, `tests/` в его конфигурации. `config.example.php` содержит только заглушки.
Дополнительная проверка MySQL: `python tests/mysql_smoke.py --php /path/to/php --extension-dir /path/to/php/ext --mysql-bin /path/to/mysql/bin`. Нужны локальные mysqld, mysql и mysqladmin. Тест сам создаёт отдельный временный экземпляр на loopback; проверяет реальную SQL-схему, повторную установку, создание администратора, ограничения попыток, utf8mb4 и транзакцию комментария с блокировкой строки. Существующие экземпляры и базы не используются. Локально проверено на MySQL 8.4.4; целевой сервер MySQL 8.0.46 также проверен: схема, права, TLS и вход администратора работают.

Общие стили подключаются напрямую из общего `php/head.php`, без дополнительной цепочки CSS `@import`. Исправлены определение заголовка страницы с query-параметрами, регистр ссылок на документы 2026 года (`Doc/`) и фиксированная высота заголовков, мешавшая длинным названиям новостей.

Возможности PHP/MySQL у 1gb.ru описаны в [документации хостинга](https://www.1gb.ru/services_compatability.php); доступность нужной версии и базы зависит от подключённых услуг вашего аккаунта.
## Подключение к удалённой базе разработки

`tools/configure_remote.py` подготовлен для отдельной установки на сервер 195.189.181.72 и выполняется только после явного согласия на изменение сервера. Он создаёт новую базу `erino5`, пользователя `erino5_dev_app` с правами SELECT/INSERT/UPDATE/DELETE только на неё и администратора с указанным email. Пароль управляющего пользователя вводится скрыто и не сохраняется; случайные реквизиты приложения и первого администратора сохраняются в приватной папке вне публичного сайта. При совпадении имён существующих базы/пользователя/файлов скрипт отказывается их менять. Частично выполненную установку нужно проверить перед повторным запуском.

Настройка `ssl: true` требует шифрованное подключение и проверяет наличие TLS после соединения. Проверка сертификата включена по умолчанию; `ssl_ca` указывает доверенный CA-файл. Только для базы разработки скрипт использует режим шифрования без проверки CA (`ssl_verify: false`), аналогичный MySQL SSL_REQUIRED. Перед боевым запуском задайте доверенный CA и включите `ssl_verify: true`.
## Установленная база разработки

На сервере 195.189.181.72 создана база `erino5` с таблицами `users`, `news`, `comments`, `rate_limits`. Приложение использует отдельного пользователя `erino5_dev_app`, которому выданы только SELECT, INSERT, UPDATE, DELETE на эту базу. Учётная запись требует TLS. Администратор сайта: `tszadmin@erino5.ru`.

Локальные реквизиты БД находятся в `D:/web/erino5.ru/.private/database.php`, начальный пароль администратора — в `D:/web/erino5.ru/.private/initial-admin.txt`. Эти файлы находятся вне публичной папки `erino5` и вне её Git-репозитория. После первого входа измените пароль администратора через личный кабинет.

Локально приложение автоматически подхватывает `.private/database.php` из родительской папки проекта, если не заданы `ERINO_CONFIG` или `ERINO_DB_DSN`. При переносе на хостинг настройте явный `ERINO_CONFIG` и включите PHP-расширения `pdo_mysql` и `openssl`. Проверка TLS-сертификата в конфиге разработки отключена; для боевого размещения задайте доверенный CA и `ssl_verify: true`.

Проверка реального подключения: `python tests/remote_check.py --php D:/web/php8/php.exe --extension-dir D:/web/php8/ext --private-dir D:/web/erino5.ru/.private`. Она использует начальные реквизиты администратора, читает схему/права и проверяет вход через временный loopback HTTP-сервер. В БД обновляются только счётчики попыток входа; тестовые новости и пользователи не добавляются. После смены начального пароля повторный тест входа требует актуальных реквизитов.

Проверено подключение с TLS_AES_256_GCM_SHA384, ограниченные права приложения, вход администратора, форма новостей, лента, доступность старой главной и запрет управления для гостей. 23 изолированных интеграционных теста также проходят. Действующий сайт erino5.ru ещё не обновлялся.
